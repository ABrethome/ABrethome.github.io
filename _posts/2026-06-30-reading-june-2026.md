**Title: Agentic retrieval - compare Snowflake and Azure offerings**

[https://www.snowflake.com/en/blog/structuring-unstructured-data-cortex-ai-functions/](https://www.snowflake.com/en/blog/structuring-unstructured-data-cortex-ai-functions/)
[https://learn.microsoft.com/en-us/azure/search/search-get-started-agentic-retrieval?tabs=windows&pivots=csharp](https://learn.microsoft.com/en-us/azure/search/search-get-started-agentic-retrieval?tabs=windows&pivots=csharp)
[https://learn.microsoft.com/en-us/azure/search/samples-python](https://learn.microsoft.com/en-us/azure/search/samples-python)
Summary: These resources show how to build enterprise AI retrieval and agent solutions using Snowflake and Azure AI Search. Snowflake Cortex AI Functions transform unstructured content (documents, transcripts, contracts) into structured, searchable data directly in SQL. Azure AI Search Agentic Retrieval uses LLMs to decompose complex queries into subqueries, retrieve relevant content, and synthesize answers. The Python samples provide end‑to‑end implementations for agentic RAG, vector search, semantic search, and knowledge-base solutions.

**Title: The Claude on Foundry Starter Kit**

[https://github.com/Azure-Samples/claude#readme](https://github.com/Azure-Samples/claude#readme)
Summary: This GitHub repository is a starter kit for deploying Anthropic Claude models (Haiku, Sonnet, Opus) on Microsoft Foundry using Azure Developer CLI, Bicep, or Terraform. It provides automated deployment, Microsoft Entra ID authentication (no API keys), integration with the Claude SDK and Claude Code CLI, and sample code for building enterprise AI applications on Azure. The goal is to quickly provision, secure, and consume Claude models in a governed Azure environment.

**Title: How to Fine-Tune an SLM for Emotion Recognition**

[https://towardsdatascience.com/how-to-fine-tune-an-slm-for-emotion-recognition/](https://towardsdatascience.com/how-to-fine-tune-an-slm-for-emotion-recognition/)
Summary: The article provides a practical tutorial for fine-tuning a Small Language Model (SLM), specifically Mistral Small 3.1, for emotion recognition. Instead of simple positive/negative sentiment analysis, the model classifies text into multiple emotions (e.g., anger, approval, disappointment). It focuses on handling highly imbalanced training data using undersampling, synthetic data generation (ISMOTE), and weighted loss functions, achieving strong accuracy for customer feedback, social media, and support analytics.

**Title: Principes de la Guerre**

[https://fr.wikipedia.org/wiki/Des_Principes_de_la_Guerre](https://fr.wikipedia.org/wiki/Des_Principes_de_la_Guerre)
Summary: Des Principes de la Guerre (Ferdinand Foch, 1903) argues that enduring strategic principles transcend technology. Applied to AI strategy, it suggests: economy of resources (focus AI investments where they create maximum value), freedom of action (avoid vendor lock-in and preserve strategic options), security (protect data, models, and operations), and concentration of effort (focus talent and funding on a few high-impact AI initiatives). The core message: victory comes from disciplined execution, adaptability, and clear strategic intent; not technology alone.

**Title: Baseline Enterprise RAG, From PDF to Highlighted Answer**

[https://towardsdatascience.com/baseline-enterprise-rag-from-pdf-to-highlighted-answer-enterprise-document-intelligence-vol-1-1/](https://towardsdatascience.com/baseline-enterprise-rag-from-pdf-to-highlighted-answer-enterprise-document-intelligence-vol-1-1/)
Summary: The article demonstrates a minimal but production-minded Enterprise RAG architecture that turns PDFs into grounded answers with highlighted source evidence. Instead of relying on complex frameworks, it uses four core components—document parsing, question parsing, retrieval, and generation—to produce auditable answers with page/line citations. The key message is that successful enterprise RAG depends on transparency, verifiability, and document engineering, not just embeddings, vector databases, or larger models.

**Title: How people are really using AI in 2026?**

[https://assets-c4akfrf5b4d3f4b7.z01.azurefd.net/assets/2026/05/2026_Work_Trend_Index_Annual_Report_050526-6_69fa654a0ab65.pdf](https://assets-c4akfrf5b4d3f4b7.z01.azurefd.net/assets/2026/05/2026_Work_Trend_Index_Annual_Report_050526-6_69fa654a0ab65.pdf)
[https://hbr.org/2026/06/how-people-are-really-using-ai-in-2026](https://hbr.org/2026/06/how-people-are-really-using-ai-in-2026)
Summary: The key message across both reports is that people use AI less as an automation tool and more as a thinking partner. The most common uses are analyzing information, solving problems, learning, technical troubleshooting, writing, brainstorming, coding, and even emotional support. High-performing users treat AI output as a starting point, not the final answer. The biggest gains come when organizations redesign workflows around human–AI collaboration and agents, rather than simply adding AI to existing processes.

**Title: 8 Ways I Reduced My AI API Bill by 60 Percent Without Any User Noticing Any Difference**

[https://ai.plainenglish.io/8-ways-i-reduced-my-ai-api-bill-by-60-percent-without-any-user-noticing-any-difference-34c6214ce30c](https://ai.plainenglish.io/8-ways-i-reduced-my-ai-api-bill-by-60-percent-without-any-user-noticing-any-difference-34c6214ce30c)
Summary: The article shares practical techniques to cut AI API costs by ~60% without reducing user experience. The key strategies are: prompt and response caching, routing simple tasks to smaller/cheaper models, compressing prompts, limiting output tokens, batching non-urgent workloads, and avoiding repeated context processing. The core message is that most AI costs come from inefficient architecture rather than model quality, and significant savings can be achieved through engineering optimization.

**Title: Vision LLMs are PDF Parsers Too: Reading Charts and Diagrams for RAG**

[https://towardsdatascience.com/vision-llms-are-pdf-parsers-too-reading-charts-and-diagrams-for-rag/](https://towardsdatascience.com/vision-llms-are-pdf-parsers-too-reading-charts-and-diagrams-for-rag/)
Summary: The article shows how Vision LLMs can act as PDF parsers for RAG, extracting not only text and tables but also the meaning of charts, diagrams, and figures that traditional OCR and document parsers miss. By converting visual content into searchable text, they make previously inaccessible knowledge retrievable. The key takeaway is to use a hybrid approach: standard parsers for text-heavy pages and Vision LLMs selectively for image-rich pages, balancing accuracy, cost, and performance.
